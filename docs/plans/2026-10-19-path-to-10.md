## What Lively is for

Lively is a native macOS 14+ menu bar utility that plays looping H.264/HEVC
video behind the desktop icons, with a separate clip (or a light/dark pair) per
display and per Space. It is for Mac users who keep several Spaces and monitors
for different kinds of work and want a live wallpaper that feels like part of
macOS: no Dock icon, no account, fully offline, and cheap enough on CPU and
battery to leave on all day. The UI is a small popover for assigning clips,
keeping a library, and a few playback and power settings; the wallpaper is the
product.

## Gaps and plan

### (a) Locally verifiable, in order of impact

1. **Privacy: never log video file names.** Remove `lastPathComponent` from log
   calls (`WallpaperController`, `ConfigStore`, `LoggerView`). Make
   `DiagnosticsRedactor` also strip any video file name (`*.mp4|mov|m4v`) as a
   second line of defence. Test-first; add a hygiene check that fails on
   `lastPathComponent` inside a `LivelyLogger` call.
2. **Perf H: stop decoding audio for muted wallpapers.** Disable the item's
   audio tracks when muted or at zero volume, re-enable on unmute. Pure policy
   in `Logic` with tests; verify with `scripts/perf/measure.sh playing` on the
   `1080p30-hevc-audio` fixture before and after.
3. **Perf A: event-driven power source monitor.** Replace the 20 s repeating
   `Timer` with `IOPSNotificationCreateRunLoopSource`. Verify that the idle
   `sample` no longer shows `__NSFireTimer`; battery-policy tests stay green.
4. **Perf E: skip no-op config refreshes.** `configStore.$configs` triggers a
   full Space refresh and retry on every publish; drop duplicates first.
5. **Docs:** record the new measurements in `docs/PERFORMANCE.md` and
   `docs/perf-findings.md`, update `CHANGELOG.md`, re-score here.

Not taken in this pass, with reason:
- Perf B (tear down the player when paused): paused is 19 MB, already inside
  the 25 MB budget; the change risks a visible black flash that cannot be
  judged without watching real hardware for a while.
- Perf G (`AVPlayerLooper`): loop spike was not visible in P1 samples, so no
  measurable before/after with the tools here.
- Splitting `ScreenCardView`: pure UI refactor with no UI test harness on CLT;
  risk outweighs benefit for this pass.

### (b) Needs the user

- **Apple Developer ID + notarization** (paid account, credentials) so users no
  longer need `xattr -dr com.apple.quarantine`.
- **GitHub Actions billing** so `ci.yml` (build, test, SwiftLint, hygiene) runs;
  then confirm `.swiftlint.yml` against real SwiftLint output.
- **Full Xcode run** of the app and tests, plus the hardware QA checklist in
  `docs/RELEASING.md` (multi-display, sleep/wake, battery).
- **`sudo powermetrics`** run for idle wake-ups and Energy Impact (needs the
  user's password).
- **Product decisions:** wallpaper behaviour under system Reduce Motion (poster
  frame vs keep playing); whether to transcode 4K/60 imports to 1080p30 or
  change the default max resolution (quality trade-off, needs a preference
  migration); whether to archive stale planning docs
  (`docs/lively_*.md`, `docs/Lively-task-list-plan.md`, `docs/TASKS.md`).
